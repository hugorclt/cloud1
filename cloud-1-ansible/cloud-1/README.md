# Cloud-1 — automated WordPress deployment with Ansible

This repository is a clean starting point for the 42 **Cloud-1** project: deploy a WordPress stack on a remote Ubuntu-like server with full automation.

It uses **Ansible only**. Terraform is intentionally not used.

## What gets deployed

- `nginx` reverse proxy container, exposed on ports `80` and `443`
- `wordpress` PHP-FPM container
- `mariadb` database container, **not exposed to the internet**
- `phpmyadmin` container, reachable only through Nginx
- Docker volumes for persistent WordPress and database data
- self-signed TLS certificate generated by Ansible
- UFW firewall allowing only SSH, HTTP and HTTPS

The deployment is designed to be repeatable and to work against one or several hosts in the Ansible inventory.

## Requirements on your local machine

Install:

- Ansible
- Vagrant + VirtualBox, only for local VM testing
- curl, for the smoke test

On macOS:

```bash
brew install ansible vagrant virtualbox
```

On Ubuntu/Debian:

```bash
sudo apt update
sudo apt install -y ansible vagrant virtualbox curl netcat-openbsd
```

## Local test

Start the local Ubuntu VM and deploy:

```bash
make local-deploy
```

Open:

- WordPress: `https://cloud1.localhost:8443`
- phpMyAdmin: `https://pma.cloud1.localhost:8443`

The certificate is self-signed, so the browser warning is expected.

If the names do not resolve on your machine, add this to `/etc/hosts`:

```txt
127.0.0.1 cloud1.localhost pma.cloud1.localhost
```

Run a simple smoke test:

```bash
make smoke
```

Stop the stack on the VM while keeping data:

```bash
make destroy
```

Delete containers and `/opt/cloud-1` data:

```bash
make destroy-data
```

## Remote VPS / AWS free-tier flow

When your VPS exists, copy the production inventory example:

```bash
cp inventories/production.ini.example inventories/production.ini
```

Edit:

```ini
[cloud1]
prod-1 ansible_host=YOUR_PUBLIC_IPV4 ansible_user=ubuntu ansible_ssh_private_key_file=~/.ssh/YOUR_KEY.pem
```

For AWS Ubuntu images, the default user is usually `ubuntu`. For a 42/Scaleway server, it may be `root`.

Then choose hostnames. Without buying a domain, `nip.io` is convenient because it resolves hostnames containing the IP automatically:

```yaml
# group_vars/all.yml
cloud1_domain: "YOUR_PUBLIC_IPV4.nip.io"
cloud1_pma_domain: "pma.YOUR_PUBLIC_IPV4.nip.io"
```

Deploy:

```bash
make deploy INVENTORY=inventories/production.ini
```

Open:

- `https://YOUR_PUBLIC_IPV4.nip.io`
- `https://pma.YOUR_PUBLIC_IPV4.nip.io`

The default TLS certificate is self-signed. For a real trusted certificate, add a domain and extend the playbook with Let's Encrypt/certbot.

## Multiple servers

Ansible can deploy to several servers in parallel. Add more hosts:

```ini
[cloud1]
prod-1 ansible_host=1.2.3.4 ansible_user=ubuntu ansible_ssh_private_key_file=~/.ssh/key.pem
prod-2 ansible_host=5.6.7.8 ansible_user=ubuntu ansible_ssh_private_key_file=~/.ssh/key.pem
```

Then run the same command:

```bash
make deploy INVENTORY=inventories/production.ini
```

## Where data is stored on the server

Ansible writes the deployment under:

```txt
/opt/cloud-1
```

Docker named volumes persist database and WordPress data:

```bash
docker volume ls | grep cloud1
```

The generated database passwords are stored on the server under:

```txt
/opt/cloud-1/secrets/
```

Do not commit private keys, `.pem` files, real passwords, or downloaded certificates.

## Useful target-side commands

SSH into the VM/VPS, then:

```bash
cd /opt/cloud-1
sudo docker compose ps
sudo docker compose logs -f
sudo docker compose restart
sudo docker compose down
```

## 42 Cloud-1 checklist covered

- fully automated deployment with Ansible
- WordPress, database and phpMyAdmin services
- one process per container
- `docker-compose.yml` generated on target
- automatic restart after reboot via Docker `restart: unless-stopped`
- persistent data through Docker volumes
- database not exposed publicly
- HTTP/HTTPS exposed through Nginx only
- TLS available through generated self-signed certificate
- several servers can be deployed in parallel through inventory
